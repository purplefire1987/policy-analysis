# 政策跟踪知识库 · 工作区（代码这一侧的唯一手册）

管理一个政策知识库：定时收集、存储政策文件，每周输出一篇观点文章，按需生成分析报告。

**两套文档，各管一件事（2026-10-29 定）**：

| 文件 | 管什么 | 谁读 |
|---|---|---|
| 资料库 `AGENTS.md` | **知识库**：写什么、什么时候写、什么算合格 | 干活的 agent、主编 |
| 本文件 | **代码**：怎么跑、怎么加检查项、判据住哪、坏了怎么修 | 改代码的人 |

以前这两件事都写在 `AGENTS.md` 里，于是「改一个检查项要不要动规则文档」长期说不清。**规则里出现 `pkb/` 的实现细节，就是放错了地方**；反过来，本文件不解释「为什么政策要按八步入库」。

## 目录

| 路径 | 是什么 |
|---|---|
| `tools/run.py` | 唯一入口（解析参数 → 路由 → 聚合退出码），动作清单见 `run.py list` |
| `tools/pkb/core/` | 机制：路径／读写／frontmatter／Markdown 解析／`Result` 契约 |
| `tools/pkb/domain/` | 口径：黑名单、来源分级、五领域、链卡映射、阈值、评分口径——**只住这里** |
| `tools/pkb/checks/` | 各项判定，只返回 `Result` 不打印；`REGISTRY` 是唯一清单 |
| `tools/pkb/actions/` | 动作实现，一模块一动作，文件名即动作名；下划线开头是内部件 |
| `tools/tests/` | 单测：解析／口径与扫描器／契约与分层 |
| `automation-prompts/` | 四个自动化的提示词存档（`旧版/` 归档历史版本） |
| `.workbuddy/memory/` | 工作日志与项目长期记忆 |

**数量不写进本文件**——动作数、检查项数、单测条数写死一次就过期一次，以 `run.py list` 为准。

## 跑

```bash
python3 tools/run.py check          # 全量自检
python3 tools/run.py list           # 列出全部动作与检查项
python3 -m pytest -q tools/tests    # 单测
```

`check` 后面可带参数，入口只把它交给**真注册**了该参数的脚本：

```bash
run.py check --since 2026-10-20   # 采集收工前核本轮信号窗口
run.py check 2026-W43             # 周观点自测某周（等价 --week）
run.py check --only docs          # 只跑名字含 docs 的项并打全量输出
run.py check --full               # 全跑且打全量输出（费 token）
```

**参数没送到必须出声**：没有任何脚本认领的参数（拼错的 `--snice`、没人认的裸周号）不允许静默丢弃——入口列 ⚠ 并以 **exit 2** 结束，明说「本次结论不含你要的那个窗口」。静默丢弃比报错危险：调用方会拿 exit 0 当已核过。

## 判读退出码

- `status`／`plan`／`week`／`list` **恒 0**，是给人看的，**不要拿它们判成败**。
- `check` 是**综合**退出码：跑完 `REGISTRY` 里全部检查项，任一项红就 1。要按单项判定（例如「信号是否采全」），读输出里**那一项那一行的退出码**，不要读整体的。
- **exit 2 ＝ 参数没送到**，此时结论**不含**你要的范围，不是通过。
- **exit 1 时改文档、不改脚本**：每条硬错误都是「某份文档在说谎」。

## 分层与契约（判据在 `tests/test_smoke.py`）

- 单向依赖：`run.py → actions → checks → domain → core`，低层不 import 高层。
- **口径只住 `pkb/domain/`**：`checks` 里出现与 domain 取值相同的字符串常量会被 `check_docs` 判错（词典从 `domain` 现读）。`core` 里允许出现 `wiki/政策卡片` 这类**目录名**——那是数据位置不是口径，判据是「是否与 domain 某取值同值」，不是「有没有出现某个词」。
- **路径只在 `pkb/core/paths.py` 定义一次**，其余模块 `from pkb.core import …`。换机器或换库位置设 `POLICY_KB_VAULT` / `POLICY_KB_WORKSPACE`，不改代码。
- **`checks` 只判定不打印**：`run()` 返回 `Result`，不 `sys.exit`；明细放 `Result.lines`，打多少由 `actions/check.py` 定。`Result.summary` **没有默认值**，不填就构造失败——「有退出码没摘要」从此写不出来。
- **单函数有效代码行**：`pkb/checks/` ≤40，其余 ≤60。只数代码行——空行、纯注释、函数开头 docstring 都不计。判据量的是「缝了几件事」，不是「写没写清为什么」。
- 快照刷新是 `check` 的第 0 步，**必须先于结构检查**，否则统计项拿旧快照报假警。

## 加一个检查项（不用改入口、不用改任何提示词）

1. 在 `pkb/checks/__init__.py` 的 `REGISTRY` **加一行** `Spec('check_xxx.py', module)`。**注册表就是清单**——文件放进目录不等于会被跑，也不按文件名自动发现（临时文件会被当成检查项跑）。
2. `Spec(..., fixable=True)` → 纳入 `fix`。认**声明**，不认源码里有没有 `--fix` 字样。
3. 需要参数的写 `Spec(..., flags=('--since','--week'))`；需要入口补 `--all` 的写 `needs_all=True`。
4. `run()` 必须 `return Result(...)`，`summary` 是一行 `▸摘要` 的结论（含关键数字与退出判定）。

## `fix` 修什么、不修什么

- **自动修**：快照数字（链卡数／政策数）、frontmatter 数值（政策数／发布日期／时间跨度）、**唯一**高度相似的断链（≥0.85 且只有一个候选）、黑名单来源链接（删链接、标待核）。
- **只报告**：观点欠账、信号断档、字段取值异常（影响／领域／tags）、跨链归属错位、文档口径冲突——都要联网或要判断。
- **两个硬边界**：`log.md` 里的链接与文字是史实，一律跳过；断链有两个以上候选时不改——猜错会把链接指到另一张卡，比断链更糟。

## 各项校验查什么

清单以 `run.py check --only <项>` 的输出为准（`run.py list` 给一句话说明），本文件不逐项抄。必须写下来的只有三条：

- **log 格式**：`## YYYY-MM-DD · 类型 · 一句话`，日期不倒序，单条 ≤80 行，类型由 `domain` 白名单限定。
- **已删页面不得再引用**：政策跟踪运营方案／政策链总览／主题词表。
- **口径单源**：`pkb/domain/` 之外的代码里不得出现与 domain 取值相同的字符串常量。

## 单测与 CI

改了 `pkb/` 就跑单测：`python3 -m pytest -q tools/tests`（无 pytest 时 `python3 -m unittest discover -s tools/tests`），全绿才算改完。单测锁的是**口径与契约**（归档周名单、黑名单、五领域、`Result` 必带摘要、分层不反向、checks 不 `sys.exit`、单函数有效代码行），不是覆盖率——它红了几乎总是「口径被顺手改了」或「函数又缝了新事」。

**push 即跑**：`.github/workflows/ci.yml` 在每次 push 与 PR 上跑 pyflakes ＋ 这套单测（**用空库跑**——空库是最强的契约输入，每项检查都会走「文件不存在」分支，正好验「任何输入都要有摘要」）。CI **不跑** `run.py check`：那是库体检，要真实知识库，守门人仍是每 2 天 22:00 的体检自动化。

## 专家包里的脚本是链接，不是第二处源

专家包的 `skills/policy-kb-tools/scripts` 是指向本仓库 `tools/` 的**符号链接**：物理上只有一份代码，漂移不必被发现，它没有发生的载体。`run.py link` 归位、`--check` 核对；`check_docs` 判**形态**——实体副本本身即硬错误，并列出与 `tools/` 的差异（那通常意味着有人把修复写在了错误的副本上，该搬回来而不是丢掉）。

**但平台还会另写一份**：`plugins/cache/<名>/<版本>/` 是它**实际加载**的那份，删不掉（2026-10-24→10-29 它落后了五天，专家定义一直缺一个自动化，而所有判据只读 marketplaces 源）。所以这一份只能**看着**：`core/expert.py::cache_drift()` 比目录树，`check_docs` 一条判据，形状不同的文件逐个点名。改完源文件必须同步进缓存，否则跑 `check` 就红——**「记得去专家中心点一次更新」不能当机制用**。

代价明说：专家包不再自包含，整包拷到别的机器不能直接跑。
