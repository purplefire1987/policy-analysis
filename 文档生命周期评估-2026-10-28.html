二、逐维说明DETAIL

1　内容获取与结构化

72

六维里唯一「机制强于执行」的一维。设计上该有的都有，落地时最关键的一处是空的。

做到了

  • 来源四档（一手／权威／门户／黑名单）＋三条整源排除，判据落在一处（domain/sources.py::level()），不是散在各处的人肉记忆。
  • 附件分「清单类」与「程序类」，并且明确「程序类不算边界，引了等于只写了正文」。这一层判断多数政策库没有。
  • run.py fetch 自动抓正文与附件、按 日期_机关_文号_标题 落盘、同 URL 跳过；只落「原文」级，报道与非一手拒收。
  • 卡片七要素 + 信号七字段，且「先砍后采」——查不到行为约束的政策只落五项事实，不硬凑判断。
  • 日期用两份独立落盘物对账（卡片小节 vs 一手存档，check_archives）：这两处不会同时错，改错就会被抓。

扣在哪

  • 157 个政策小节，没有一个引过清单类附件——「附件」这一栏直到今天才第一次存在。一手性最该落地的地方（边界：管到哪、管多少、谁在内）恰好是空的。
  • 存档没有回流：raw/articles/ 有 37 份，卡片里提到存档的只有 1 张。存档的价值是「链接断了还查得到」，卡片不指过去，这个价值就没兑现。
  • 一手存档 37 份对应 157 个政策小节，约 四分之一；其余靠官网链接，链接一断就没有第二份。
  • 文号栏今天才补出来，其中 16 处仍是「（待补全）」——而文号是检索任何一条政策的唯一稳定键。
  • 个别卡的「政策原文」仍指向门户（如人民币国际化报告指向 mpaypass.com.cn），属「能点开≠能核验」。

2　格式转换

68

六个维度里分最低的一维。不是做得差，是只做了一半方向。

做到了

  • HTML → 文本的四个坑全部写进代码并修好：GBK 编码（部委站按 UTF-8 解会整页乱码，而乱码只是「看起来没有正文」）、正文容器（切全文会把导航条混进来）、附件扩展名（商务部是 download?fileName=xxx.docx，按路径取会得到 download，于是附件转换永远跳过）、gzip（某些站不讲条件就回压缩流）。
  • docx / doc / pdf → 文本，不引第三方依赖：docx 用 zip+XML、doc 借系统 textutil、pdf 用已装的 pdfminer；装不上就在存档里注明，不静默丢。
  • 附件不留原件只留文本——为的是可 grep。这个取舍是对的：不能检索的附件等于没存。
  • 每个坑的成因写在实现里而不是别处，下一个人改这段代码时不会重新踩。

扣在哪

  • 出库方向是零：md → docx / pptx / pdf 完全没有。分析报告、周观点要给别人看，得另找工具排版，而且版本会分叉。
  • 无 OCR：扫描件 PDF 转出来是空串（会被注明，但那一份的边界就拿不到了）。
  • 表格结构不保留：合并单元格、图片化表格在文本化后丢失，正好是「清单类附件」最常出现的形态。

3　编辑与版式

76

思想是对的——「模板即清单」，规则文件不抄结构。今天补上了这套思想缺的最后一环。

做到了

  • 六个模板各管一种产出；周观点节数、信号字段从模板现读，AGENTS 里明写「本文件不抄」——抄一次就多一处会静默过期的副本。
  • 结构可校验：周观点节名与模板逐字比对、分析报告八节、卡片每小节六个小标题。
  • 今天之前，模板要求的「文号」「附件」「基本信息五项」「影响判断三行」一条判据都没有；现在每一栏都有检查点（_check_info_box / _check_section），并用 9 个用例钉住。
  • 「收录政策 N 项」这类与 frontmatter 同义的副本被删掉——同一个量两处写必然漂（已漂 5 张卡）。

扣在哪

  • 判据只到「标题在不在」「值等不等」，正文质量（是否照抄标题、是否空话）脚本判不了，只能靠验收清单里那几条「人判」项。
  • 卡片正在变大而没人管：金融卡 76 KB（约 3.8 万 token）、出口管制卡 74 KB。提示线是 2 万字符，超了只提示，没有拆卡或压缩机制——而每次插入新政策都要读入这张卡。
  • 没有排版引擎，所有产出都是 Markdown；对外交付要靠另一套工具，版式风格无法统一。

4　安全合规与审计

79

来源合规是全系统最锋利的一段判据；扣分几乎集中在一件事上。

做到了

  • 黑名单域名扫描命中即 exit 1，且判据不是「域名在表里」，而是「域名归属 ≠ 标注媒体」即违规——这一条比黑名单本身更难绕过（冠名转载、看点号、网易号），并点名了十个高危域名。
  • raw/ 只读 + 唯一例外（fetch 只落「原文」级）。目录名是承诺：一份记者稿躺在 articles 里，两年后就会被当成一手用。
  • 四页留痕各管一件事：采集日志管「采到哪天」、运行状态管「跑没跑」、任务台账管「修没修」、log 管「为什么这么定」。四者不可互相替代。
  • 改前自动备份（今天改 33 张卡前打了 tar 包）；沙箱与安全中心的实际行为被查清并写进台账，不是猜的。
  • 「数字只有一个出口」：台账未关闭行写裸读数会被 check_docs 判错——今天我自己写了一个「157」就被当场抓住。

扣在哪

  • 资料库不在 git。33 张卡、15 条链、121 条信号、5 篇周观点没有任何版本历史——改错了没法 diff、没法回滚，只能靠 tar 全量备份倒退。这是六维里最大的单点缺口。
  • 审计只能 grep：log.md 已 1,063 行，查「这条口径哪次改的」要靠人翻。
  • 无访问控制与敏感分级（当前是单机单人、内容全是公开政策，所以没出事；换个场景不成立）。
  • 归档物搬进 归档/ 后不再被任何检查扫到，等于出了防线。

5　自动化与 AI 增强

80

六个维度里最高的一维。分工、边界、扩展方式都立住了，缺的是「出错时怎么办」。

做到了

  • 三个自动化职责单一、互不通信，文件是唯一交换介质——耦合度低，一个坏了不会连带。
  • 单一入口：13 个动作、9 个检查项，REGISTRY 就是清单；加检查项只改一处，不改文档、不改提示词。
  • 扩展约定写死四条：注册一行、fixable=True 才进 fix、参数要声明、Result.summary 无默认值（「有退出码没摘要」写不出来）。
  • CI 每次 push 跑 pyflakes + 空库 pytest——空库是最强的契约输入，每项检查都会走「文件不存在」分支。
  • 「脚本不猜，猜了就是编造」：断链有两个候选就不改，状态只报不判，判断留给人。这条边界是全系统最值钱的设计。
  • AI 用在它该在的地方（写观点、写辨析、找分歧），不用在它不该在的地方（判真假、改口径）。

扣在哪

  • 三个自动化互不通信，靠时间窗错开：体检挂了采集照跑；周观点在 10:30 启动，若采集延后就可能读到半成品，而它无法知道。
  • 不告警：灯变 🟡 要人主动去看。今天的体检结论是「已跑但 0 新增」，这需要人判断是「没采到」还是「今天真没政策」。
  • 不重试：check_health 只报「根本没跑」，不触发补跑，补偿全靠人。
  • 无自动去重/摘要：同一政策在卡片、信号、周观点里各写一遍，没有一处做「这三处说的是不是同一件事」的核对。

6　归档与生命周期

77

机制设计得很干净（只搬不删、幂等、默认 dry-run），但触发条件与覆盖面有缺口。

做到了

  • 四态 + 三个到期日写在 domain/lifecycle.py 一处；ledger --apply 默认只看、加参才写、幂等。
  • 归档不是删除：整行进「关闭记录」，编号全局唯一，grep 得着——这是「不删行」与「别让账本变垃圾堆」之间唯一可行的折中。
  • 「验没验」只报不判：脚本替人下结论就是编造。
  • 归档分层清楚：归档/（判断台账、旧提示词）、归档/备份/（tar 包）、raw/articles/（一手原文）。
  • log 压缩过两次，每次都写清删了什么、原本记哪、为什么还留一条；清理前原文进备份。
  • 卡片「状态」四值，旧小节不删只标「已废止（被 X 取代）」。

扣在哪

  • 归档由体检触发（90 天到期靠每 2 天的体检搬行），体检一停就积压——而体检本身没有告警。
  • 归档/ 没有索引页，找东西靠 ls；归档物不被 check 扫描，链接断了也没人知道。
  • 只有归档没有删除。33 张卡已经 902 KB，按现在的增速，两年后单卡读一次就是几万 token。
  • 没有「保留策略」：什么该留、留多久、什么可以压成摘要，没有口径。

三、最该先改的三件事NEXT

按「补上之后能防住多少其他问题」排序，不按工作量。

把资料库纳入 git

这是唯一能兜住「改错」的机制，而现在恰好没有。今天改 33 张卡、157 个小节，靠的是 tar 包——tar 只能整体倒退，不能告诉你「这张卡哪个字段在什么时候被谁改了」。raw/ 可排除（37 份存档不进版本库，另有备份），只跟踪 wiki/、templates/、AGENTS.md、log.md。做与不做，决定后面所有改动是有据可查还是一次性赌注。

让一手存档回流到卡片

37 份存档、157 个政策小节、卡片里引用存档的只有 1 张。存档建了却不被读，等于建了一条没人走的备用路。改动很小：卡片小节在「政策原文」处同时写 [[{存档文件名}|原文存档]]，判据可以是「有存档而卡片未引 → 提示」。同时把「清单类附件」补进最需要的那几类（出口管制、关税、配额）——那是 157 节里唯一 0 覆盖的栏位。

给自动化加一道「前置检查」和一次「失败告警」

现在三个任务靠时间窗错开，互不知道对方成没成。最小改法：周观点开跑前先看运行状态，采集最近一轮不是今天就把结论标「本期数据截止 X 日」；体检发现「根本没跑」时写一条显式告警（哪怕只是在运行状态里标红）。不知道自己在读旧数据的报告，比没有报告更危险——它看起来是新的。

评分方法：六个维度各 100 分，等权平均。每一条「做到了」都能在代码或文件里指到落点，「扣在哪」全部是本次盘点中实际观察到的现象（检查项报告、文件计数、代码路径），不是推测。
数据来源：run.py check 九项输出、pytest 278 passed、资料库文件计数、tools/ 代码通读。
为什么写「75.3」而不是「85」：这套系统已经有的东西比多数同类项目好（判据单一出口、脚本不猜、模板即清单），但它的失效率集中在「判据覆盖不到的地方」——那些地方看起来和工作的地方一模一样，都是绿的。评分反映的是能放心把哪一步交出去，不是已经写了多少。
