# 18:00 采集轮 · 执行记忆

> 只记「每轮都要用得上」的东西，不记单轮产出（产出在库内 [[采集日志]]）。

## 轮次号规则

- 轮次号**跨两轮连续递增**，不分 09:00／18:00。写前先 `run.py status` 看「最近轮次」，取下一个整数。
- 2026-10-29 实际：09:00＝第三十八轮，18:00＝第三十九轮。

## 窗口

- 本任务窗口＝**今日 09:00 ~ 18:00**（AGENTS 第五节）。不按自然日切。
- `check --since` 传 `"2026-10-29 09:00"` 这种带时刻的串，脚本认。

## 每轮固定动作（按序）

1. `status` → 取轮次号与灯
2. `plan` → 领活；第 3 段若写「本次领这页」，**先改台账「最近领取」再检索**，否则重跑会重复领同一页
3. `check --since {窗口起}` → 看 `check_signals` 那一行
4. 检索：骨架（国常会／国新办／部委发布会／全会）→ 门户补网
5. 写信号 → 回填观点（T+1 先于存量）
6. `fetch` → `check` → `check --since`
7. 三页留痕：采集日志加行／运行状态覆盖采集行＋加记录／台账改状态
8. `check` 复检（留痕会改动文档，必须再跑一次）

## 踩过的坑

- **政府网「最新政策」栏会漏掉只走通讯社快报的部委规划**（2026-11-01 实测）：国家文物局《考古工作"十五五"规划》10-19 印发、10-31 经新华社权威快报披露，政府网该栏没有它，两轮都漏。**处置**：除该栏外，还要扫「新华社权威快报／部委官网规划栏」；发现漏采按「政策信息不丢优先」补录并在备注写明「上轮窗口漏采、本轮补录」，不要因为落在窗口外就当没看见。
- **`check_signals --since {当天}` 周日也会判「1 个工作日无信号」**：脚本的工作日口径与日历不一致，周日同样报红。这不是漏采，**不要为过检查去记普通工作动态**，在采集日志与运行状态里写明「窗口内 0 条、周日实况」即可。
- **新增小节会同时抬高覆盖率分母**：本轮新增《考古规划》并留观点占位，回填 3 个后覆盖率是 89.0%→89.7%（148/165）而非 90.2%（148/164）。**留痕前先跑一次 check 取真实比数再写**，别按「145+3/164」心算。

- **设备休眠会让两轮挤在一起跑，窗口塌成几分钟**（2026-11-01 实测）：18:00 任务在本轮于 `2026-11-01 00:5x` 才被触发，而 09:00 任务（第四十二轮）恰在 `00:55` 收工——两轮相隔不到 5 分钟，按「上一轮时点→本轮时点」取窗口只剩数分钟，政策必然 0。**处置**：① 不因窗口为空而跳过留痕；② 把有料的部分（上轮漏采的那一天、存量补采、观点配额）如实做完；③ 备注写清「实跑时点偏移」与真实窗口，不要沿用名义时点蒙混。**副作用**：`check --since {今天}` 会因凌晨空窗口报「1 个工作日无信号」——改传含上轮漏采日的那一天（本轮传 `2026-10-31`）即真实反映覆盖，不要为此补记普通工作动态。
- **写采集日志时用 Edit 替换整行会把上一轮行删掉**（2026-11-01 实测）：先 grep 行号再插，或把「新行 + 被顶掉的那行」一起写进 `new_string`。已当场核回并补回第四十二轮行（备注写明「由第四十三轮补回」，不藏）。
- **存量页「核了但没信号」也必须前移游标**（2026-11-03 修）：11-01 与 11-03 两轮都领「十五五总体规划」、都写「无符合门槛信号、游标未前移」，等于同一批 10-17~10-30 反复核、永远推进不了。判据改成：**本批逐日核毕即把「已补至」推到批次末日**，剩余天数由「今天−已补至」自然算出，回落进 14 天阈值就出队。游标管的是「核到哪」，不是「补到几条」。
- **`check_health` 的「0 新增」判的是「新增政策」列**：窗口内只有信号、没有新政策时，它会报「已跑但 0 新增（没采到，非漏跑）」并给 🟡。这是**格式判据而非事实判据**——须在采集日志备注里写清「政策 0、信号 N」，别据此去重跑自动化。
- **存量页剩余天数落到 ≤14 天就出队**：`plan` 会单列「可归档」并把该页从队列里拿掉；状态改 ✅ 时要写清「断档已回落至阈值内，未补部分按日历逐日核、不再占名额」，别直接写「已清零」——10-22 之后确实还没补。
- **`run.py fetch` 窗口只有「今天+昨天」**：本轮回填的是信号与观点、没有新政策，摘要行「卡片 0 条」是正常的，不是失败。
- **政府网「最新政策」栏（`gov.cn/zhengce/zuixin/`）比搜索引擎可靠**：全会公报这种「有文号无编号」的会议文件只在「要闻」栏，不在「最新政策」栏，两处都要看。
- **全会／政治局会议公报走信号、不走政策卡**：公报无文号。库内既有先例是「开幕」记一条信号、「公报」再记一条并判「继续」（增量在通过与细化）。
- **门户转述的研报数据不能当官方统计**：写进观点表须标「门户转载」并在辨析里注明「未回官方核，以研报口径限定」。
- **公众号（含专家长文）不能作出处**：`mp.weixin.qq.com` 在黑名单，即便文章质量高也只能读来定方向、不能进来源列。
- **09:00 轮写过「下轮补核」的事项会落在本轮的备注需求里**：先读当日 09:00 那一行备注，再开检索。
- **台账行改错列的后果是硬错误**：本轮把「本轮再增一张」追加到 T-20261028-07 时插在行尾 `|` 之后，列数 8→9，`check_docs` 立即报「多半是两条粘成一行」。**追加内容必须落在末列内部、收尾 `|` 之前**。
- **未闭环行不许写裸读数**：往 🟡 行里写「21083 字符」会被 `check_docs` 判违例，改写「同步越过提示线，读数跑 `check --only structure` 现取」即过。
- **`fix` 会刷快照**：check 第 0 步报「1 处待更新」时先跑 `fix`，再跑 check 才是最终结论。
- **存量页补完后 `plan` 会把该页列为「可归档」**：断档回落到 ≤14 天即出队，状态改 ✅ 但行保留。

- **无人值守采集轮可以拆卷**（2026-11-02 实拆 [[政策卡片-对外贸易与开放]] 为 3 卷，全程无用户参与，`check_structure` 该卡体积警告即刻消失）。旧结论「拆卷留待有用户在场的轮次」不成立，已写进 T-20261028-07；剩下能源／法治建设／双碳三张可照同法直接拆。
- **往表格插整行时，`old_string` 不能只截旧行前半段**：`Edit` 会用新内容替换匹配段、**保留旧行剩余部分**，于是旧行尾巴被粘到新行末尾——列数往往不变，`check_docs` 不一定报，只有逐行数 `|` 才看得见（2026-11-02 本轮在运行状态运行记录上连踩两次）。正确做法：`old_string` 取到该行行尾 `|`，新内容里把「新行＋旧行整行」一起写全。
- **留痕会改变 check 输出**：`check_health` 比的是采集日志轮次与运行状态灯写法是否一致、`check_vcs` 计未提交数——留痕写完再跑一次才是最终读数。备注里别写「要知道 N 条」这类写完就过期的量。
