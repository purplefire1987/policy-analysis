## 四、tools（四层）

- **分层单向**：`run.py → actions → checks → domain → core`，低层不许 import 高层。
- **`core` 不含口径**（名单/枚举/判据），但**可以有目录名与结构名**（`wiki/政策卡片`、`### 日期 · 标题`）——前者是「规则是什么」，后者是「数据在哪」。判据是「与 domain 某取值同值」，不是「出现某个词」。
- `core/`：paths（唯一路径）／fs（`py_files(TOOLS)` 是「哪些文件该导出/校验」唯一出口）／fm／md／web（curl 抓取，见坑 21）／report（`Verdict`＋`Result`，**`summary` 无默认值**→「有退出码没摘要」写不出来）。
- `domain/`：blacklist／fields／chains／legacy／**automations（自动化 ID 名单）**／**lifecycle（三档到期日）**。**口径只能住这里**。
- `checks/`：**10 项**＋`REGISTRY`（`Spec(name, module, needs_all, flags, fixable)`）。**注册表即清单**，不按文件名发现；`run()` 返回 `Result`、不打印、不 `sys.exit`。10-26 增 `archives.py`（卡片日期 × `raw/articles/` 存档日期交叉核：文号→标题包含，差 >10 天报；**查不出两边一起错**，输出里明写这句）。`docs` 是**包**（9 个模块，按「被核对对象」分组：declared／consistency／ledger／expert_pkg／hygiene／dnsource／literals ＋ `_state`；执行顺序即报告顺序，**不许重排**）。
- `actions/`：11 个动作 `status／check／fix／plan／week／fetch／ledger／link／sources／list／query`（`query` 2026-10-28 新增：按词／链／时间窗检索，输出「文件:行号」，只检索不判断；与 `week` 共用 `core/md.scan_dated()` 的切法，**边界不许两处各写一份**）。**一模块一动作，文件名即动作名，下划线开头是内部件**；`ACTIONS` 与模块由 `test_smoke` 钉一一对应，`list` 从包里发现。参数按**真注册**判定，无认领 **exit 2** 并明说结论不含该窗口。
- **摘要行契约**：`Result.summary` 就是 `▸摘要`；明细在 `lines`，打多少由 `actions/check.py` 决定（`--only`／`--full`）。
- **`check_health`**：三分状态 `正常`／`已跑但 0 新增`（没采到，别重跑）／`根本没跑`；交叉核「灯 vs 日志」与「0 也写 0」（固定生效 2026-10-24）。
- **`check_docs` 的两类硬核**：① **结构数字扫全文档**（卡/链/受控词/信号字段，报文件＋行号；台账、报告、log 是当时快照**不入扫描**）；② **口径单源扫描**（`ast` 取字符串常量，与 `pkb.domain.__all__` 现读词典比对，`REQUIRED_FIELDS` 排除；词典不另写，domain 加一项自动覆盖）。另：规格文档清单 `SPEC_DOCS`＝AGENTS／index／政策速览／专家定义／专家包 README／SKILL。

## 五、踩过的坑（按类合并）

**判据类**
1. **自愈机制必须被验证过一次才算存在**：`--fix` 正则写全角冒号而库里用半角，从建立起没修成过也不报错。
2. **判据必须是真声明，不能靠文本包含**（注释含 `--fix` 就被编进修复队列）；**AST 优于逐行正则**（docstring 里举的例会被当代码——第一版口径扫描把 `docs.py` 自己的 docstring 判成违规）。
3. **判据写进解释性文本会被自己误伤**：`sys.exit(` 被 docstring 里的「原来是 print + sys.exit(2)」误报；`python3 -m pkb…` 写进 AGENTS 就被直调正则判违规。判据认**调用形态**，说明文字用描述性措辞。
4. **白名单拼进识别正则会让自己失效**：`LOG_HEAD` 曾用 `'|'.join(LOG_TYPES)` 构造，类型写错的条目匹配不上、落进「历史条目」被静默豁免，那条报错分支从未触发过——「类型限五类」等于不存在。识别放宽成任意串、白名单另查才验得出来。
5. **声明了取值范围就要有判据**：台账写「裁判只能取手册第三节列过的」而脚本不管；加上后第一条数据就不对（写「财政部预算公开」，手册叫「预算与决算公开」）。名单**从文档现读、不在代码里存第二份**。
6. **宁可宁窄不错认**：全库扫 `N 节` 把 `政策链三节`、`六节历史归档` 这类**正确**写法判错。**会误伤正确写法的规则比不扫更糟**——它教人以后绕开规则。10-26 又栽一次：台账取值表（采集／体检／周观点／分析／断档／结构）进了 domain 的 `__all__`，口径扫描立刻报 11 处**正确**写法（paths 的目录名、status 的灯标签）。通用词做枚举时**别进口径扫描词典**，只让需要它的检查 `import pkb.domain.xxx` 直接读。
7. **写死名次＝写死数量**：手册「前四项任一成立即可否掉」是补裁判前写的，后来加了 3 类裁判，判定权还锁在旧四项里。**名单加长时，凡带序号的判据都要回头看一眼。**
8. **静默丢弃比报错危险**：拼错的参数照跑 exit 0，调用方以为窗口核过了。

**文档类**
9. **没有校验的副本等于迟早撒谎**：4 次事故全是库外副本漂移；**单源化本身就是修漏洞**（黑名单合并时发现两份已漂移）。
10. **结构化断言查不出叙述性描述**：10-26 审计实证 6 处漂移全在「脚本会自动发现」「raw 只读」这类句子——**文档漂移只能人读**，别把脚本当完整防线。
11. **副本清单要按「谁在读它」核**：专家包 README／SKILL 长期在防线外（写着七节、动作表漏 fetch/ledger、教人跑已删脚本），无人报。
12. **「读了这个文件」≠「核对了这个文件」**：`_load_docs()` 把 index 读进来却没有检查消费它，「核对 AGENTS／index」听起来是真的。
13. **log 标题日期位只认单一日期**：`## 2026-10-24 ~ 10-25 · …` 匹配不上 `LOG_HEAD`，被当历史条目，其后全部新条目被判错位。区间写正文。
14. **「已归档」必须当场核文件存在**：两处写着「原样归档于 X（499 行）」而目录**根本不存在**，686 行不可检索。**写「已归档」比不写更坏**——后人以为还能查就不补了。此后做法：路径＋行数＋当场 `ls`。
15. **删东西前先 grep 引用，包括「同义词指路」**：删了 313 行采集流水，而「明细见采集日志」这类句子 grep 链接名抓不到，结果两份文件互相指路、流水谁那儿都没有。
16. **改文档最容易顺手编一个看起来对的分布**：「9 条」拆成「腾讯 2、财联社 1…」是推算的没数过。**没有逐条数过就写「逐条见附表」**（两次犯同一病）。
17. **带日期的相对量不是两本账**：台账「78→72」与「78→73」是 10-25／10-26 两个时点，断档按天自然 +1。**改数前先看是不是不同时点的同一个量。**

**环境类**
18. **macOS 是 BSD grep**：`grep "a\|b"` 不支持 `\|` 交替，静默无输出。用 `-E` 或 Grep 工具。
19. **`HTTP_PROXY` 会让 curl 访问 localhost 返回 502 且退出码 0**：探端口用 bash `/dev/tcp` ＋ `NO_PROXY`。macOS bash 3.2 会吞紧跟变量的全角字符（须 `${VAR}`）。
20. **并行子代理必 429**，批量补录走主通道；`%%` 注释不成对会吞正文（用 `<!-- -->`）；能点开≠能核验。
21. **止损不等于治因**：一手存档正文乱码，先加 `looks_binary()` 只拦住结果；真因是该站无条件回 gzip 而 `curl` 没带 `--compressed`，`decode(errors='ignore')` 把压缩流拼成「看着像字」。**结果不对，往回追一层问从哪步开始不对。**
22. **osascript 删文件可能返回 -10004 而文件已进废纸篓**：以源目录文件数为准。

采集日志管「采到哪天」（**0 也写 0，禁 `—` 与留空**）／运行状态管「跑没跑」（灯）／任务台账管「修没修」（🆕→🟡→⏳→✅／⛔／🚫，只改状态不删行）。台账含三个游标（断档补采、存量队列、清欠进度）。**第四本账**＝判断台账，管「判没判」，`check_judgments` 逐条回原文。

## 七、文档纪律

规则只写一处；同一批事实只列一张表；易变数量不写死（读数一律跑 `plan`／`check --only` 现取；只有**结构常量**可写进文档）；log 只回答「当时为什么这么定」。
**副本归零（2026-10-28）**：动作表、信号字段表、硬门槛表**一律不进文档**——动作跑 `run.py list`（从 `ACTIONS` 直接长出）、字段以模板为准、硬门槛写「四个时点必跑」。起因是加一个动作原要改五处（`ACTIONS`／AGENTS／专家定义／体检提示词／SKILL）；`check_actions()` 已随之删除，**「核 N 份副本是否一致」不如「不留副本」**——前者的核对清单自己也会漂。结构数字扫描因此从 23 处降到 22 处，是它该走的方向。
**log 压缩是例外，须留交代**：至今压过三批（10-24 两条超长、10-26 采集流水 313 行与专题改稿 127 行），整理前原文在 `归档/备份/政策库备份-20261026-log整理前/`。折叠条要写清删了什么、原本记哪、为什么还留一条；**摘要须覆盖被合并的每一条**。

**一句话原则**：合格评的是过程不是命中率；**九条全对、没有一条可能错，是最坏的结果**。

**补观点时真正稀缺的不是条数，是分歧**（10-27 实证）：同一条政策，官方解读、券商点评、行业媒体常复述同一段文件语言，凑够五条不难但零信息。只有两类值得进「观点辨析」——① 对同一事实给出**互不兼容的机制解释**（例：购房贴息的机会成本说／银行信贷说／中央信号说，各对应一个观察指标，事后每方都能自称言中）；② **数字打架而分歧来自测算口径**（例：同笔 100 万 30 年贷款，官方「近 5 万」vs 逐年摊销 4.6 万，差异在还款假设不在政策）。数字分歧不能当观点分歧写，也不能只抄一个数字。另立固定栏目「必须拦住的外推」——写观点最常犯的错不是引错人，是把文件里一句话顺推成结论（「利率降三分之一」≠月供降三分之一；「规模不设上限」≠人人可享；「工资专用账户」≠工资上涨；「一企一策」≠地方松绑）。
