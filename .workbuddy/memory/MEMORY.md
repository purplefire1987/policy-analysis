## 五、踩过的坑

1. **自愈机制必须被验证过一次才算存在**：`--fix` 正则写全角冒号而库里用半角，从建立起没修成过且不报错。
2. **判据必须是真声明不能是文本包含**（check_docs 因注释含 `--fix` 被误编进修复队列）。
3. **没有校验的副本等于迟早撒谎**：4 次事故全是库外副本漂移；今天起动作表也纳入 check_actions。
4. **单源化本身就是修漏洞**：黑名单合并时发现两份清单已漂移。
5. **静默丢弃比报错危险**：拼错的参数照跑 exit 0，调用方以为窗口核过了。
6. 并行子代理必 429，批量补录走主通道；`%%` 注释不成对会吞正文，用 `<!-- -->`；能点开≠能核验。
7. **判据写进解释性文本里会被自己误伤**：`sys.exit(` 判据被 docstring 里的「原来是 print + sys.exit(2)」误报；`python3 -m pkb…` 写进 AGENTS 说明就被直调正则判成违规。判据认**调用形态**（行首调用／ast 常量），说明文字用描述性措辞。
8. **macOS 是 BSD grep**：`grep "a\|b"` 不支持 `\|` 交替，会静默无输出（排查时白白怀疑文件编码）。用 `grep -E` 或 Grep 工具。
9. **AST 优于逐行正则**：注释/docstring 里举的例不能被当代码；第一版口径扫描把 `docs.py` 自己的 docstring 判成违规。
10. **白名单拼进识别正则会让自己失效**：`LOG_HEAD` 原用 `'|'.join(LOG_TYPES)` 构造，类型写错的条目匹配不上、落进「历史条目」分支被静默豁免，那条 `bad_type` 报错分支从未触发过——「类型限五类」等于不存在。识别放宽成任意串、白名单另查，才验得出来（10-26 审计发现）。
11. **结构化断言查不出叙述性描述**：`check_docs` 查节名、动作表集合、结构数字、引用有效性，但专家定义里「脚本会自动发现」「raw 只读」这类句子它不报。10-26 审计实证 6 处漂移全在叙述层——文档漂移只能人读，别把脚本当完整防线。
12. **写死名次＝写死数量**：深读手册「前四项任一成立即可否掉一条判断」是补裁判前写的，后来表尾加了 3 类裁判，判定权却还锁在旧四项里——按字面执行，产业政策最常用的三类裁判被降成「仅供参考」。**名单加长时，凡带序号的判据都要回头看一眼。**
13. **log 标题的日期位只认单一日期**：写成 `## 2026-10-24 ~ 10-25 · 决策 · …` 匹配不上 `LOG_HEAD`，被当成历史条目，其后所有新条目被判「追加在历史之后」。区间写进标题正文，别占日期位。
14. **改文档时最容易顺手编一个看起来对的分布**：整合台账时把「9 条」拆成「腾讯 2、财联社 1…」——构成是推算的、没逐条数。**没有逐条数过就写「逐条见附表」。**
15. **`run.py list` 的说明是副本**：「10 个动作」现算不会漂，但每行说明取自各模块 **docstring 首行**，改 docstring 就得回头看 AGENTS 里对 list 的描述。
16. **「已归档」必须核过文件存在**：log 两处写着「全文原样归档于 `<路径>`（499 行／187 行，未删一字）」，而 10-26 查实该目录**根本不存在**（工作区、Spotlight、废纸篓皆无），686 行不可检索。**写「已归档」比不写更坏**——它让后来的人以为还能查，于是放心地不补。压缩的前提是真留了底，不是一句交代；此后的做法是「路径＋行数＋当场 ls 一遍」。
17. **删东西之前先 grep 引用，包括「同义词指路」**：10-26 删掉 log 里 313 行采集流水，没查谁在引用它，结果 `采集日志` 有三处「见 log.md」、两整行「见 log.md」，而 log 那条折叠记录又写着「明细见采集日志」——**两份文件互相指路，流水谁那儿都没有**。「明细见 X」这种句子不算引用形态，grep 链接名抓不到。
18. **「读了这个文件」≠「核对了这个文件」**：`check_docs._load_docs()` 把 index.md 读进来，却没有任何一项检查读那个键，于是「核对 AGENTS／index／README」这句话听起来是真的。我改这句话时还照着它又抄了一遍。**负载而不消费的读盘，是把「已核对」演给读者看。**
19. **带日期的相对量不是两本账**：台账两行分别记「断档 78→72」「78→73」，看着像打架，实为 10-25 与 10-26 两个时点，断档按天自然 +1，`plan` 现报 73。**改数之前先看两个数是不是不同时点的同一个量**——本轮差点"修"掉一个对的数。
20. **专家包的 README／SKILL.md 长期在防线之外**：`check_docs` 的节名比对只读 AGENTS 与专家定义，`check_actions` 只读 AGENTS 与专家定义两张表——于是 README 写着「七节结构」（实为八节）、动作表漏 `fetch`/`ledger`、教人跑三个 10-25 就删掉的脚本，全部无人报。**副本清单要按"谁在读它"核，不是按"它在不在库里"核。**

## 六、三页分工

采集日志管「采到哪天」（**0 也写 0，禁 `—` 与留空**）／运行状态管「跑没跑」（灯）／任务台账管「修没修」（🆕→🟡→⏳→✅／⛔／🚫，只改状态不删行）。台账含三个游标（断档补采、存量队列、清欠进度）。**台账的生命周期由 `run.py ledger` 推**（10-26 增）：三档到期日住 `domain/lifecycle.py`（✅ 90 天归档／🟡 3 天退回／⏳ 7 天待验过期／备注「观察窗口」到期），`check_docs` 的 `check_ledger_hygiene` 只报不阻断、`run.py ledger --apply` 才搬行；**默认 dry-run + 幂等**，归档＝整行进第六节 + 表下留汇总，不删行。`plan_backlog` 常数 `STOCK_GAP=14／STOCK_BATCH=14／GAP_BATCH=2／GAP_TRIGGER=3／VIEW_DAILY=3／VIEW_WEEKLY=5／CLAIM_PER_CHECK=1`，**领取闸门＝体检节拍**。体检产出＝三页，须写「本期释放了哪页哪批」。

**台账结构有判据（10-26 增）**：`check_docs` 的 `check_ledger_shape` 判三条——T- 行只能住「未闭环项」（8 列）与「关闭记录」（5 列）、列数＝表头列数、未闭环项内编号唯一（跨节同号不算重复，否则会逼人删归档行）。起因是两条记录被粘成一行，`plan` 按**行首**取编号，后半条静默消失两天没人发现。**列数是最灵敏的探针**——两条粘一行必然多出列，判形态不会被措辞骗。另：存量队列「剩余天数」＝今天−已补至（未开补用首次空白日、含头含尾），是相对量、每天自然 +1，体检核的是「已补至前移后它降没降」，不是绝对值。
