## 三、tools（四层）

- **分层单向**：`run.py → actions → checks → domain → core`，低层不许 import 高层。
- **`core` 不含口径**（名单/枚举/判据），但**可以有目录名与结构名**——前者是「规则是什么」，后者是「数据在哪」。判据是「与 domain 某取值同值」，不是「出现某个词」。
- `core/`：paths（唯一路径定义处）／fs（`py_files(TOOLS)` 是「哪些文件该校验」唯一出口）／fm／md（`scan_dated` 切 `### 日期 · 标题`；`scan_notes` 切整篇）／web／report（**`summary` 无默认值**→「有退出码没摘要」写不出来）。
- `domain/`：blacklist／fields／chains／legacy（`IMPACT_SINCE`）／automations／lifecycle／ledger（`LEDGER_COLS`）。**口径只能住这里。**
- `checks/`：**9 项**＋`REGISTRY`（`Spec(name, module, needs_all, flags, fixable)`）。**注册表即清单**，不按文件名发现；`run()` 返回 `Result`、不打印、不 `sys.exit`。`docs` 是**包**，执行顺序即报告顺序，**不许重排**。
- `actions/`：**13 个**，**一模块一动作，文件名即动作名，下划线开头是内部件**；与 `ACTIONS` 由 `test_smoke` 钉一一对应（**动作清单只在 `run.py list` 一处，不进文档**）。参数按**真注册**判定，无认领 exit 2 并明说结论不含该窗口。三个检索口（2026-10-28）：
  - `query`：按词／链／时间窗，出「文件:行号」，只检索不判断；`--notes` 才查人的笔记。与 `week` 共用 `scan_dated`，**边界不许两处各写一份**。它还把「这词也是某几张卡的关键词」一并列出（按卡看整块政策，不管正文有没有这个说法）。
  - `trace`：政策→卡→链→信号→一手存档；查不到用 `difflib` 给最近三条。**补的是「能查词不等于能查关系」。** 卡与卡的关系靠 `mentioned_by` **按文号反查**（题名常被简称，手写链接必断；库里卡间 `[[政策卡片-X]]` 本来就是 0 处，39 处卡内链接全指向链）。`archives_of` 只按文号／题名认存档，同日候选单列 `same_day`——**按「日期相同」认领会把同一天的无关文件算成原文，假阳性比查不到更坏**。O(n²) 遍历必须 `lru_cache` 缓存读文件。
  - `recent`：近 N 天新增（`--days/--kind/--limit`），无日期的单独计数**不替它猜日期**但要明说排除几条。补的是「有没有空转」。
- **卡片「关键词」是有判据的入口**（2026-10-28）：此前在必填字段里却无人读值，坏成块式列表／切进 Markdown 列表号都没人知道。判据在 `check_structure`（块式、非数组、列表号、含空格、重复各报，少于 3 个只提示）；消费端＝`query`（按卡兜底）与 `trace --card`（第一行打关键词）。口径：**写别名与上位词，把标题里已有的词抄一遍等于没写**。
- **摘要行契约**：`Result.summary` 就是 `▸摘要`；明细在 `lines`，打多少由 `actions/check.py` 定（`--only`／`--full`）。
- **`check_health`**：三分 `正常`／`已跑但 0 新增`（没采到，别重跑）／`根本没跑`；交叉核「灯 vs 日志」与「0 也写 0」。
- **`check_docs` 的两类硬核**：① **结构数字扫全文档**（卡/链/受控词/信号字段，报文件＋行号；台账、报告、log 是当时快照不入扫描）；② **口径单源扫描**（`ast` 取字符串常量，与 `pkb.domain.__all__` 现读词典比对，`REQUIRED_FIELDS` 排除）。另校台账表头契约与 log 结构。规格文档 `SPEC_DOCS`＝AGENTS／index／政策速览／专家定义／专家包 README／SKILL。

## 五、踩过的坑（按类合并）

**判据类**
1. **自愈机制必须被验证过一次才算存在**：`--fix` 正则写全角冒号而库里用半角，从建立起没修成过也不报错。
2. **判据认声明形态，不认文本包含**：注释含 `--fix` 就被编进修复队列；docstring 里举的例会被逐行正则当代码。用 **AST**；说明文字用描述性措辞，否则 `sys.exit(`、`python3 -m pkb…` 这类解释性引用会自己误伤自己。
3. **白名单拼进识别正则会让自己失效**：`LOG_HEAD` 曾用 `'|'.join(LOG_TYPES)` 构造，类型写错的条目落进「历史条目」被静默豁免，报错分支从未触发——「类型限五类」等于不存在。
4. **声明了取值范围就要有判据**：台账写「裁判只能取手册列过的」而脚本不管；加上后第一条数据就不对。名单**从文档现读、不在代码里存第二份**。
5. **宁可宁窄不错认**：全库扫 `N 节` 把 `政策链三节`、`六节历史归档` 这类**正确**写法判错。**会误伤正确写法的规则比不扫更糟**——它教人以后绕开规则。通用词（采集／体检／周观点／结构）做枚举时**别进口径扫描词典**。
6. **写死名次＝写死数量**：手册「前四项任一成立即可否掉」是补裁判前写的，加了裁判后判定权还锁在旧四项。**名单加长时，凡带序号的判据都要回头看一眼。**
7. **静默丢弃比报错危险**：拼错的参数照跑 exit 0，调用方以为窗口核过了。

**文档类**
8. **没有校验的副本等于迟早撒谎**：4 次事故全是库外副本漂移；**单源化本身就是修漏洞**。副本要按「**谁在读它**」核——专家包 README／SKILL 长期在防线外，无人报。
9. **结构化断言查不出叙述性描述**：漂移全在「脚本会自动发现」「raw 只读」这类句子——**文档漂移只能人读**。「读了这个文件」≠「核对了这个文件」（`_load_docs()` 把 index 读进来却没消费它）。
10. **log 标题日期位只认单一日期**：`## 2026-10-24 ~ 10-25 · …` 匹配不上 `LOG_HEAD`，被当历史条目，其后全部新条目被判错位。区间写正文。
11. **「已归档」必须当场核文件存在**：两处写着「原样归档于 X（499 行）」而目录**根本不存在**。**写「已归档」比不写更坏**。做法：路径＋行数＋当场 `ls`。
12. **删东西前先 grep 引用，包括「同义词指路」**：「明细见采集日志」这类句子 grep 链接名抓不到，结果两份文件互相指路、谁也不含流水。
13. **改文档最容易顺手编一个看起来对的分布**：「9 条」拆成「腾讯 2、财联社 1…」是推算的没数过。**没有逐条数过就写「逐条见附表」**。
14. **带日期的相对量不是两本账**：台账两个数字常是两天时点的同一个量，断档按天自然 +1。**改数前先看是不是不同时点。**

**环境类**
15. **macOS 是 BSD grep**：`grep "a\|b"` 不支持交替，静默无输出。用 `-E` 或 Grep 工具。
16. **`HTTP_PROXY` 会让 curl 访问 localhost 返回 502 且退出码 0**：探端口用 bash `/dev/tcp` ＋ `NO_PROXY`。bash 3.2 会吞紧跟变量的全角字符（须 `${VAR}`）。
17. **并行子代理必 429**，批量补录走主通道；`%%` 注释不成对会吞正文（用 `<!-- -->`）；能点开≠能核验。
18. **止损不等于治因**：一手存档正文乱码，先加 `looks_binary()` 只拦住结果；真因是该站回 gzip 而 `curl` 没带 `--compressed`。**结果不对，往回追一层问从哪步开始不对。**
19. **osascript 删文件可能返回 -10004 而文件已进废纸篓**：以源目录文件数为准。
20. **沙箱内一切删除都失败，临时目录因此全不可用（2026-10-28 定因）**：安全中心文件规则默认「删除=询问」，工具执行期没有确认框＝拒绝；生成的 seatbelt profile 末尾 `(deny file-write-unlink (subpath "/"))` 排在所有 allow 之后，而规则是**后匹配覆盖先匹配**——写成功、删全败（沙箱日志自己记 `静/动裁决不一致 allow_drift=1`）。证据在 `~/.workbuddy/logs/sandbox/<日期>/sandbox_*_000.log` 的 profile 段。后果：`tempfile` 判「建了能删」全不通过 → `gettempdir()` 抛错，**每次 Python 启动在四个候选目录各留一个 8 字符随机名空文件**（无扩展名垃圾的源头，清完还长）；`pytest` 起不来（捕获用 `TemporaryFile`，open 后立刻 unlink；要跑得 `-s` ＋ 把 `tempfile.tempdir` 指到工作区 ＋ 清理容错，**这种绕法不进代码**）。`run.py fetch` 已改成不依赖 `tempfile`（工作目录 `.cache/fetch/work/<时间戳>/`）。用户 2026-10-28 决定不改删除权限，**别反复试删**。
21. **症状是「全都失败」而不是「个别失败」时，先读完整上下文，别找特例**：这次连查三轮策略、清 safe-delete 残留，答案其实就在每次执行的日志头几行。`git index.lock` 残留同属此列——交给用户清。

- **代码侧只记三处易忘的**：`weeks.py::_missing_head` 按编号判结构；`docs.check_week_sections` 不写死节数（模板即清单）；`_match` 同分按「归一化后逐字相同」裁决——否则同批模板化公告会按行序通吃。
- **补观点时真正稀缺的不是条数，是分歧**：只有两类值得进「观点辨析」——① 对同一事实给出**互不兼容的机制解释**（各对应一个观察指标）；② **数字打架而分歧来自测算口径**（官方「近 5 万」vs 逐年摊销 4.6 万，差异在还款假设不在政策）。数字分歧不能当观点分歧写；「利率降三分之一」≠月供降三分之一。

## 九、人的落笔处：`raw/notes/`

**为什么在 `raw/` 下而不在 `wiki/` 下**：它不是「库的结论」，是**输入**。周观点取消判断与定稿后，人的异议要有地方写；写在产出里会被下次生成覆盖。机器只读不写。

- 一篇笔记一个文件，日期与标题在 frontmatter，**结构自由**——所以用 `scan_notes` 而不是硬套 `scan_dated`。笔记不进卡片、不进信号，**除了检索没有别的入口，进不了结果就等于没写**。
- **周观点生成时读上一期笔记，相左处并列不裁决**：`> **分歧**：〔笔记的结论〕——本刊的结论是〔…〕`，谁对由下期数据说。
- **合格评的是过程不是命中率**，看的是「该核的核了没有、核不动的说清了没有」。
