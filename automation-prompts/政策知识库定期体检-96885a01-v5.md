**8.1 体检报告 `wiki/总览/体检报告.md`（台账式，不许覆盖历史）**
- **顶部「当前未闭环项」**：与任务台账同源，只列负责环节＝体检的项（编号、首次发现、问题、状态、最近更新）。采集负责的用一句指回任务台账，不在这里重复列。
- **「本次检查摘要」**：**各脚本的退出码**（不写「共 N 条命令」）、快照改了几处、统计指标（产业卡数、政策小节总数、真实断链数、观点覆盖率 a/b/c、信号合计条数与断档分布、近 7 天采集缺口天数）、**文档一致性一行**（check_docs 结论：硬错误 N 项／提示 N 条）、**log 卫生一行**、**「本期释放」一行**（哪一页／哪一批，或为什么没释放）。
- **「历次检查记录」最上面追加一节** `### YYYY-MM-DD HH:MM — 第 N 次`：**只写变化**——哪些指标升了降了（与上期比，不列全表）、本期新增问题、本期关闭问题、遗留、本期释放的页／批次。**旧节一个字都不改**——这是「不覆盖」的全部意义。
- 单列四份清单：T+1 未闭环、待补全、无观点、超期未补。若与上期完全相同，写「与上期一致（N 条）」，不必重复罗列。
- 保留「下一轮应核对的事项」。

**8.2 运行状态 `wiki/总览/运行状态.md`**
- 覆盖「当前状态」表里**体检**那一行：最近运行、退出码（写「全部 0」或点名非 0 的那个）、本轮产出、遗留、灯（🟢/🟡/🔴 按该页判定表，不许凭感觉）。**「最近运行」必须写成当次运行的真实日期时间**——它是采集领取存量页的闸门，写错或留空，队列就会多领或冻住。

- 顺带核对另外两行的灯是否已经过期（例如采集超过一个节拍没有新记录 → 应改 🔴，并登记任务台账）。这属于只报告，可以改灯，不可替它补采。

**8.3 任务台账 `wiki/总览/任务台账.md`**
- **新增**：本期新发现的问题登记新行，编号 `T-{YYYYMMDD}-{nn}`。类型/负责环节按该页取值填，负责环节要写对人（内容欠账→采集；报告与校验口径→体检；文档漂移→体检）。
- **改状态**：本期已验证的改 ✅ 并写关闭依据（脚本退出码、文件、日期）；做了但没验的改 ⏳ 待验。**已 ✅ 的行不许删**，超过 90 天由本任务移到「关闭记录」节。
- **退回**：标 🟡 在办超过 7 天、而对照台账无任何动作记录的，退回 🆕 并注明「久未推进」。
- **超期点名**：报告里单列「超期未闭环（>14 天）」清单。
- **不动两个队列的数据行**：存量补采队列与断档游标的「已补至／剩余天数／最近领取」由采集回写，体检只核对推进情况，不改这些格（改了会让采集的游标与真实进度错位）。
- 不许擅自关闭「负责环节＝采集」的项，除非有脚本或文件证据（如覆盖率上升、信号页已有条目）。

【九·log 的处理（校验优先，写入从严）】
log.md 自 2026-10-24 起只管两件事：**口径或结构的变更**、**事故与复盘**。例行采集、例行体检、周观点一律不进——它们已在采集日志／运行状态／任务台账留痕，再抄进 log 就是第四本账，且是唯一无校验的一本。
1. **校验**：`check_docs.py` 已给出格式、倒序、篇幅、重复标题与体积结论，报告里单列一行「log 卫生：N 条新格式条目／N 条超长／体积 N KB」。硬错误（格式不合、日期乱序、新条目被追加到文末）列入「待修」，由本任务当场修格式（只动格式，不改内容）。
2. **写入**：只有本期**发生了口径/结构变更**或**修复了事故**，才向 log.md 追加一条，格式 `## YYYY-MM-DD · 类型 · 一句话`，**置顶插入**（本库 log 为新在上），单条 ≤80 行，正文只写：改了什么、为什么、依据哪份文件或脚本、还需谁确认。例行体检不写。
3. 不改写任何历史条目，不删历史。
