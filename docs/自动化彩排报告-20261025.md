## 零·怎么彩的（以及为什么不是真跑）

按三份提示词逐条抽取命令，**只读命令全部真跑**，写入动作只做前置校验不落盘。理由两条：

1. 真跑采集会在 [[采集日志]] 多记一轮、在卡片里重复插入同一批政策，而今天 09:00 的第三十四轮已经采过 10-24 09:00～10-25 09:00 的窗口；
2. 真跑周观点会覆盖已定稿的 `周观点-2026-W42`，而 W43 的素材要到明天 09:00 采集后才齐。

所以本报告验的是**命令能不能跑通、退出码含义对不对、提示词说的库内锚点在不在**，不验检索质量。

### 彩排抓到的 bug（已修）

**B1 `--since` 不接受时间点，且失败时不留摘要行。**
提示词第三节 5 让传「窗口起点」，窗口起点是**时刻**（昨天 09:00），agent 极可能写成 `--since "2026-10-24 09:00"`。原实现直接 `date.fromisoformat()` 抛错 → `sys.exit(2)`，**连 `▸摘要` 都不打印**，入口那一行是空白：

```

```
采集看到「exit 2」会以为是参数拼错（提示词确实这么写），于是**跳过信号核查直接开工**——一个合法调用被判成非法，还静默。已改为：取日期部分（窗口粒度本来就是天），并在两条失败分支都补摘要行。验证：`2026-10-24 09:00`／`2026-10-24T09:00` 通过；`昨天`、`W43` 给出 `▸摘要: … 无法解析，本次未检查（结论不含该范围）⚠`。

### 彩排抓到的 bug（已修）

**B2 周覆盖校验对「归档周」两套判据，同一事实两个结论。**
`--all` 走名单外推断（「有没有信号节」→ 视为归档 → 不计退出码），单周 `--week` 却没这层豁免。结果：体检按提示词对近 4 周逐周跑，**W40／W41 每周都报 exit 1**（漏 3～4 项），而这两周是用户已决定不回补的六节旧篇。体检每两天看到一次同样的红灯，只有两种结局：写成「采集失效周」，或者反复登记台账。

已改为单源判据 `LEGACY_WEEKS = {W39, W40, W41}`，两条路径共用；顺带补掉一个反向漏洞——原来「新写的周观点若漏了信号节」会被自动当成归档周判**通过**，现在漏节是硬失败：

```
✗ 缺「二、本周政策信号」节：七节模板要求该节必在，只有 LEGACY_WEEKS 名单内的归档周可豁免
▸摘要: 2026-W43 结构缺节：无「二、本周政策信号」  ❌
```

另外，**周观点文件不存在时原来也不打印摘要**（exit 2），现在是 `▸摘要: 2026-W43 周观点尚未生成（无文件，不是覆盖不足）❌`——「没生成」和「覆盖率低」是两件事，措辞必须分开，否则体检会把产出缺失当覆盖不足去追采集。

**B2 的另一半：副本漂移当场被抓住。**
我只改了 `tools/check_signals.py`，没跑 `run.py export`，下一次 `check` 立刻 exit 1：

```
✗ [专家包] 内容已变（改了 tools 未同步）：check_week_coverage.py
✗ [专家包] 副本已漂移——跑 `run.py export` 重新同步，不要在专家包内直接改
```
这是设计意图，不是故障——但它证明**这套机制在有真实改动时确实会响**，比任何口头保证可靠。

## 四·风险清单

按「会不会真的出事」排序，不按代码位置排。

### R1　周观点 08:00 早于采集 09:00，周日深夜的政策永远赶不上当周（**最高**）

采集每天 09:00 跑，窗口是「昨天 09:00～今天 09:00」。所以**周日 09:00 之后发布的政策，要等周一 09:00 那一轮才入库**；而周观点周一 08:00 就写完了。

后果不是「漏一条」这么简单：周一 22:00 体检跑 `check --week 2026-W43`，此时库里已经有了那几个周日深夜条目，而 W43 速览表里没有 → **判漏项 exit 1**，并登记「W43 覆盖不足」。周观点当时是对的，一天后变成错的，**而且修不掉**（重写要等下周一的采集素材，回补又违反「窗口外不列」）。

三条出路：
| 方案 | 动作 | 代价 |
|---|---|---|
| A（推荐） | 周观点 `BYHOUR=8` → `10:30`，让采集先跑完 | 改 1 个 rrule；提示词里「上周一至上周日」表述不变 |
| B | 采集提前到 07:00 | 采集要联网检索，07:00 前出结果不稳；且与签到自动化（09:30）无关，风险低但收益只是给周观点腾 1 小时 |
| C | 周观点接受「以周一 08:00 库内为限」，并在文末注明 | 不改配置，但每次体检都要人工解释一遍红灯 |

> 这是唯一需要你点头的一条，因为它动的是自动化配置，不是代码。

### R2　台账行内嵌过期数字，与 `plan` 输出互相打脸（中）

`plan` 第 1 段照抄台账描述：`T-20261024-02｜三张信号页长期空白：国防军事 78 天（最近 08-07，5 条）`；而同一份 `plan` 第 3 段写 `国防军事 断档 72 天（最近 2026-08-14，共 6 条）`。因为 10-25 已经补过一页，**台账那句话是当时的快照**。

采集看到两处矛盾，只能自己判断信哪个——**这正是「两本账」的老问题**。建议：台账「问题」列不写会变的数字，只写问题本身（「国防军事页长期空白」），现状数字一律以 `plan` 为准。

### R3　提示词让「按历史归档标记识别」，库里其实没有这个标记（中，已改）

> 更正：本节初稿写成「体检提示词」，实际那句话在**周观点**提示词的零节末尾；体检提示词从未出现该表述。

三份归档周观点（W39/W40/W41）里既没有 `历史归档` 字样，也没有相同的说明块（W40 有一句「本篇为变更前归档」，W39/W41 一个字都没有）。也就是说，**这段规则在任何文档里都无法被核验**，只能靠脚本里的 `LEGACY_WEEKS` 名单。名单本身没问题，问题是提示词让 agent 去「按标记识别」，而标记不存在。

已改为：「豁免判据在脚本名单里，**不是文内标记**——不要给旧篇补「历史归档」字样，补了也不改变判定」。体检侧同时补了一句「周覆盖那行写『历史归档』即退出码 0、属正常，不得登记台账」。

### R4　提示词让往「index.md 的周观点分区」追加，实际是 `一、知识` 下的 `###` 子节（低）

真写的时候很可能被理解成新建一个 `## 周观点` 顶级节。改成「`index.md` → `一、知识` → `### 周观点（wiki/周观点/）` 小节末尾追加」即可。

### R5　体检的「第 N 次」与库内「第四次」写法不一致（低，纯观感）

提示词写 `### YYYY-MM-DD HH:MM — 第 N 次`，历史节是 `### 2026-10-24 23:09 — 第四次（…）`。下次会写成「第 5 次」，同一份报告里两种写法。建议提示词改成「沿用中文序数，如「第五次」」。

### R6　采集若同一天重跑，存量页可能被重复领（低）

`plan` 第 3 段的「本次领这页」是**读台账算出来的**，采集没写回台账前重跑一次，拿到的还是同一页。后果是同一页补两遍（浪费额度，不丢数据）。建议 `plan` 输出里加一句「领取后先改台账再开工」。

### R7　副本漂移只有红灯，没有自动修复（低，且是刻意设计）

`check_docs` 发现漂移只 exit 1，不会自动 `export`——这是对的（副本不能自己变回源头）。但它意味着**每次改脚本都必须记得跑 `export`**，忘了就会在体检里亮红灯，由人处理。彩排中我自己就踩了一次。

### R8　体检 22:00 那次会「回头看」当天 08:00 的周观点（低，已随 R1 缓解）

若 R1 选 A（10:30），08:00→10:30 之间周观点若失败，22:00 体检会看到「尚未生成」并按采集/观点环节登记——逻辑正确，属于预期行为，无需改。
